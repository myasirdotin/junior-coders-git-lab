Grades 9–10

🛡️ Cybersecurity Cheat Sheet

Strong passwords, spotting scams, protecting websites and keeping data safe on one page, in the same order as the Cybersecurity textbook. Defence only.

Two habits: never trust input (use prepared statements and encode output), and never store a password, only a slow salted hash made with password_hash(). Long, random and unique beats short and complicated.
🔺 The CIA Triad & Principles
ConfidentialityOnly the right people can read the data (TLS, AES)
IntegrityNobody can change the data unnoticed (hashes, HMAC)
AvailabilityThe service works when people need it (backups, spare servers)
Least privilegeGive each person or program only the access it needs
Defence in depthSeveral layers, so one failure is not a disaster
AmānahPeople's data is a trust you must actively protect
🔐 Encoding, Hashing & Encryption
Encoding (Base64, URL)Changes the format only. No security at all
Hash (SHA-256)One-way fingerprint: checks a file was not changed
Password hash (bcrypt, Argon2id)Slow on purpose and salted; Argon2id also needs lots of memory
Symmetric (AES-256-GCM)One shared key locks and unlocks; fast
Asymmetric (RSA, ECC)Public key locks, private key unlocks; used to agree a shared key
Digital signature (Ed25519)Private key signs, public key checks who sent it
🔑 Password Strength
bits = length × log₂(choices)Only true when every part is chosen at random
123456 sunshineOn every list of common passwords: found instantly
8 random characters ≈ 52.6 bitsAbout 4 days*
5 random words ≈ 64.6 bitsAbout 44 years*
6 random words ≈ 77.5 bitsAbout 340,000 years*
7 random words ≈ 90.5 bitsNeeded for 80+ bits; far out of reach
* the times aboveAverage at 10 billion guesses a second on a fast hash
Words from a list of 7,776About 12.9 bits each; let a generator pick, never a famous phrase
Website rules (NIST 2025)Allow long passwords (15+ when it is the only factor), no forced symbols or regular changes, block leaked passwords
🎣 Spotting Phishing & Scams
Hurry or fear"Your account closes in 1 hour!" is a warning sign
Check the real addressRead the name before the first single / from the right: in school.example.org.evil.test the owner is evil.test
Asks for a password or codeReal services never ask for your password or 2FA code
Unexpected attachment or prizeDo not open it; check with the sender another way
Report itTell a teacher or parent and use "Report phishing"
🛡️ OWASP Top 10 (2025) & Fixes
A01 Broken Access ControlCheck the user owns the record on every request (changing ?id= must not work)
A02 Security MisconfigurationHide error details, change default passwords
A03 Software Supply Chain FailuresUpdate libraries; install only from trusted sources
A04 Cryptographic FailuresHTTPS everywhere; slow hashes for passwords
A05 InjectionPrepared statements (SQL); encode output (XSS)
A06 Insecure DesignPlan how the feature could be misused before building
A07 Authentication FailuresLimit guesses, offer 2FA, slow password hashes
A08 Software or Data Integrity FailuresInstall only updates you can check came from the maker
A09 Security Logging & Alerting FailuresRecord failed logins and someone looks at them
A10 Mishandling of Exceptional ConditionsWhen something fails, deny access; never let people in
💻 Safe SQL Prepared Statements
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = ?");PHP PDO: the SQL has a ? placeholder
$stmt->execute([$email]);The value is sent separately, never as SQL
cursor.execute("SELECT * FROM users WHERE email = ?", (email,))The same idea in Python sqlite3
db.execute('SELECT * FROM users WHERE email = ?', [email])The same idea in Node.js mysql2
"… WHERE email = '$email'"Never: gluing input into SQL allows injection
htmlspecialchars($name)Encode text before showing it in a page (stops XSS)
🧂 Proper Password Hashing
$hash = password_hash($password, PASSWORD_DEFAULT);Store a slow, salted bcrypt hash ($2y$…)
PASSWORD_ARGON2IDUse Argon2id instead, where your PHP supports it
if (password_verify($typed, $hash)) { … }Check a login against the stored hash
md5() sha1() hash('sha256', …)Never for passwords: billions of guesses a second
🌐 HTTP Defensive Headers
Strict-Transport-Security: max-age=31536000; includeSubDomainsBrowser must use HTTPS for a year
Content-Security-Policy: default-src 'self'Load scripts and media only from this site
Content-Security-Policy: frame-ancestors 'none'No other site may show this page in a frame (clickjacking)
X-Frame-Options: DENYThe older header for the same job
X-Content-Type-Options: nosniffBrowser must trust the declared file type
Referrer-Policy: strict-origin-when-cross-originSend less of your address to other sites
Permissions-Policy: camera=(), microphone=()Turn off features the site does not need
🍪 Session Cookies & CSRF
HttpOnlyJavaScript cannot read the cookie (limits XSS damage)
SecureSent over HTTPS only
SameSite=Lax / StrictNot sent on most requests from other sites; helps against CSRF
CSRF tokenA secret random value in every form, checked by the server; use it as well as SameSite
Max-Age=3600The cookie ends after 3600 seconds (1 hour)
🧼 Digital Hygiene Checklist
Password managerA different long, random password for every account
2FA / MFAAn authenticator app or security key; turn it on for email first
UpdatesInstall system and browser security updates soon
3-2-1 backups3 copies, on 2 kinds of storage, 1 kept somewhere else
Public Wi-FiUse only HTTPS sites, a trusted VPN if you have one, and avoid important logins
Photo metadata (EXIF)Remove location data before sharing pictures
Amānah (trust) rule: these skills are for defence. Test only your own sites and computers, or ones you have written permission to test, and report a weakness you find to its owner instead of using it.
