Authentication 🔐

Secure login, registration, and user sessions — built into Laravel!

What is Authentication?

Authentication is the process of verifying who a user is. When someone logs in with their email and password, your app checks if those credentials are correct, then remembers who they are for the rest of their session.

Starter Kits — Quick Auth Setup ⚡

You do not have to build login pages yourself. A starter kit is a ready-made set of pages and code. It gives your app register, login and logout pages, plus the routes and controllers behind them.

Since Laravel 12, the official starter kits are built with React, Vue or Livewire. Projects on Laravel 11 and earlier usually used a starter kit called Breeze.

# 1. Install the Laravel installer once (it adds the "laravel" command) composer global require laravel/installer # 2. Create a new app. The installer asks which starter kit you want. laravel new school-portal # 3. Build the page files (CSS and JavaScript) npm install && npm run build # 4. Create the users table php artisan migrate

npm is a tool that downloads JavaScript packages. It comes with Node.js. The installer may already run steps 3 and 4 for you, and running them again is safe. After these steps, your app has working register, login and logout pages.

The Auth Facade 🎭

The Auth facade is your tool for working with the currently logged-in user anywhere in your app:

use Illuminate\Support\Facades\Auth; // Check if someone is logged in if (Auth::check()) { echo "Welcome back!"; } // Get the logged-in user object $user = Auth::user(); echo $user->name; echo $user->email; // Get just the user's ID $id = Auth::id(); // Log the user out Auth::logout();

In Blade templates you can use the same via the auth() helper:

@auth <p>Hello, {{ auth()->user()->name }}! 👋</p> <form method="POST" action="{{ route('logout') }}"> @csrf <button type="submit">Log Out</button> </form> @endauth @guest <a href="/login">Log In</a> <a href="/register">Register</a> @endguest

Logging out uses a small POST form with @csrf, not a plain link. The logout route only accepts POST with a CSRF token, so another website cannot log your users out with a hidden link.

Protecting Routes with Middleware 🔒

The auth middleware automatically redirects guests to the login page if they try to access protected routes. Wrap any route you want to protect:

// Protect a single route Route::get('/dashboard', [DashboardController::class, 'index']) ->middleware('auth'); // Protect a group of routes Route::middleware(['auth'])->group(function () { Route::resource('students', StudentController::class); Route::get('/profile', [ProfileController::class, 'show']); });

The logout route only accepts a POST form with a CSRF token, and a link sends GET. The route needs the auth middleware.

@auth
    <form method="POST" action="{{ route('logout') }}">
        @csrf
        <button type="submit">Log out</button>
    </form>
@endauth

Route::get('/my-books', [MyBooksController::class, 'index'])
    ->middleware('auth');

🔴 Level 3: Challenge

On your own XAMPP computer, build a "My reading list" page that only library members can see.

  1. Create a new project with a starter kit, as shown above. Connect it to a MySQL database (see Module 5, Level 3) and run php artisan migrate.
  2. Start the server. Register an account for yourself on the register page.
  3. Make a ReadingListController with an index() method. It gets the logged-in user with Auth::user() and passes it to a view.
  4. Add the route /my-reading-list and protect it with the auth middleware.
  5. In the view, greet the member by name. Add a logout form inside @auth, and log in and register links inside @guest.
  6. Log out, then try to open /my-reading-list. You should be sent to the login page.
Show one possible answer
// routes/web.php
use App\Http\Controllers\ReadingListController;

Route::get('/my-reading-list', [ReadingListController::class, 'index'])
    ->middleware('auth');

// app/Http/Controllers/ReadingListController.php
use Illuminate\Support\Facades\Auth;

public function index()
{
    $user = Auth::user();
    return view('reading-list', compact('user'));
}

<!-- resources/views/reading-list.blade.php -->
@auth
    <h1>Assalamu alaikum, {{ $user->name }}!</h1>
    <p>Your reading list is empty. Visit the library to add a book.</p>
    <form method="POST" action="{{ route('logout') }}">
        @csrf
        <button type="submit">Log out</button>
    </form>
@endauth

@guest
    <a href="{{ route('login') }}">Log in</a>
    <a href="{{ route('register') }}">Register</a>
@endguest

Because the route uses auth, a guest never reaches this view. The @guest part is there for when you reuse it on a public page.
