Level 2

HTTP Deep Dive & Wire Format 📬

The core protocol of the World Wide Web. Learn what travels through the wire when you click a button or fetch an API.

Asking and Answering: The Order Slip 📝

🧠 Real-life analogy: At the school book counter, you hand over a slip. It says what you want to do ("borrow"), which item ("Science Grade 8") and any notes ("paperback, please"). The librarian hands back a reply slip. It starts with a short result ("Ready" or "Not in stock"), then any notes, then the book itself. HTTP works exactly like these two slips.

HTTP (HyperText Transfer Protocol) is the set of rules browsers and servers use to ask for and send web pages, pictures and data. The browser is the client: it asks. The server answers. Every exchange is one request and one response.

The Parts of an HTTP Message

In HTTP/1.1, a message is plain text in four parts:

  1. Start line. In a request: the method (what to do), the path (which item) and the version. In a response: the version and the status code (the result).
  2. Headers. Extra notes, one per line, written as Name: value.
  3. An empty line. It marks the end of the headers.
  4. The body (optional). The actual content, such as a web page or form data.

The most common methods are:

  • GET: read something. It has no body.
  • POST: send new data, such as a form.
  • PUT or PATCH: replace or change something that exists.
  • DELETE: remove something.

Worked example 1: a GET request and its response

A student searches a library catalogue for science books. The browser sends:

GET /books?topic=science HTTP/1.1     ← start line
Host: library.example.org             ← headers
Accept: text/html
                                      ← empty line
                                      (no body for GET)

The server answers:

HTTP/1.1 200 OK                       ← status line
Content-Type: text/html; charset=utf-8
Content-Length: 5120
Cache-Control: max-age=600
                                      ← empty line
<!DOCTYPE html>                       ← body begins
<html> ... list of science books ...
  • Host says which website is wanted, because one server can host many sites.
  • Content-Type says what the body is: an HTML page written in UTF-8 characters.
  • Content-Length says the body is 5,120 bytes long.
  • Cache-Control: max-age=600 lets the browser reuse this page for 600 seconds (10 minutes) without asking again.

Worked example 2: sending data with POST

A relief charity's app records a donation of blankets. The body is JSON, a simple text format for data.

POST /api/supplies HTTP/1.1
Host: relief.example.org
Content-Type: application/json
Content-Length: 34

{"item":"Blankets","quantity":500}

The body is exactly 34 characters, so Content-Length is 34. The server replies:

HTTP/1.1 201 Created
Location: /api/supplies/77
Content-Type: application/json
Content-Length: 42

{"id":77,"item":"Blankets","quantity":500}

201 Created means a new record was made. The Location header tells the app where to find it.

The 5 HTTP Status Code Classes

A status code is a three-digit number. Its first digit tells you the kind of result.

1xx Information

101 Switching Protocols: "let's change to another protocol" (used by WebSockets, Module 8).

2xx Success ✅

200 OK, 201 Created, 204 No Content (done, nothing to send back).

3xx Redirection 🔀

301 Moved Permanently (go to a new address), 304 Not Modified (your saved copy is still fine).

4xx Client Error ⚠️

400 Bad Request, 401 Unauthorized (please log in), 403 Forbidden (you are not allowed), 404 Not Found.

5xx Server Error 💥

500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable (busy or under repair).

A simple rule: 4xx means the request had a problem. 5xx means the server had a problem.

Worked Example 3: Reading Real Headers With curl 🖥️

curl is a command-line tool that sends HTTP requests. It comes with Windows 10 and 11, macOS and most Linux systems. The -I flag asks for the headers only.

curl -I https://example.org/

In Windows PowerShell 5, type curl.exe instead of curl. There, the short word curl runs a different PowerShell command.

Example output (shortened; real headers will differ):

HTTP/2 200
content-type: text/html
content-length: 1256
cache-control: max-age=3600
date: Mon, 12 Oct 2026 08:00:00 GMT

Notice HTTP/2 and the lowercase header names. HTTP/2 writes header names in lowercase. The meaning is the same as in HTTP/1.1.

Use curl -i (small i) to see the headers and the body together.

From HTTP/1.1 to HTTP/2 and HTTP/3

Head-of-line blocking is like a canteen queue. If the person at the front is slow, everyone behind them waits. Each new HTTP version reduced this waiting.

  • HTTP/1.1 (plain text): one request at a time on each connection. A slow reply holds up the next one. Browsers open several connections to work around this.
  • HTTP/2 (binary, which means computer-friendly codes instead of text): many requests share one TCP connection as separate streams. Headers are compressed. But if one TCP segment is lost, TCP pauses every stream until it is resent.
  • HTTP/3 runs on QUIC, a protocol built on top of UDP (Module 4). QUIC does its own checking and resending for each stream. A lost packet only pauses its own stream. Encryption is built in. A download can also keep going when a phone moves from Wi-Fi to mobile data.

Common Misunderstanding ⚠️

"404 means the server is down."

No. A 404 is an answer, so the server is working. It only means there is nothing at that path. A server that is truly down sends no answer at all, and the browser eventually gives up.

"POST is secret and GET is not."

Without HTTPS (Module 7), both travel as readable text. POST does keep data out of the address bar and out of most server logs. That is why passwords are sent with POST, and always over HTTPS.

🏆 Practice: three levels

🟢 Level 1: Recall

What do these status codes mean: 201, 404, 503? Which class (first digit) means the server had a problem?

Show answer
201 Created (a new item was made), 404 Not Found (nothing at that path), 503 Service Unavailable (the server is busy or under repair). The 5xx class means a server problem.

🟡 Level 2: Apply

Read this response and answer: (1) Did it work? (2) What kind of content is the body? (3) For how many minutes may the browser reuse it?

HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: max-age=1800
Content-Length: 39

{"item":"Water bottles","quantity":200}
Show answer
(1) Yes: 200 OK. (2) JSON data (application/json). (3) 1800 ÷ 60 = 30 minutes.
