Level 2

Transport Layer: TCP vs. UDP 🚚⚡

Guaranteed reliability vs. lightning-fast speed. Understand handshakes, sockets, and ports.

Two Ways to Deliver: Courier or Loudspeaker 🚚📢

🧠 Real-life analogy: TCP is like a careful courier. Before delivering, the courier phones to check you are home. Every parcel is signed for. If one goes missing, the courier sends it again. UDP is like the school loudspeaker. The announcement goes out at once. Nobody signs anything. If you miss a word, it is not repeated, but the announcement keeps going.

The transport layer (Layer 4) carries data between two programs, not just two computers. The two main transport protocols are TCP (Transmission Control Protocol) and UDP (User Datagram Protocol).

Ports: Numbered Doors on a Computer 🚪

One computer runs many programs at once. A browser, an email app and a video-call app may all use the network together. How does an arriving segment find the right program?

The answer is a port number. A port is like a numbered door on the computer. Each program listens at its own door. Port numbers go from 0 to 65,535. Numbers 0 to 1,023 are "well-known" ports kept for common services.

80
HTTP (web)
443
HTTPS (secure web)
22
SSH (secure remote command line)
53
DNS (name lookups)

An IP address plus a port number is called a socket. It is written with a colon, for example 203.0.113.10:443. The server listens on a well-known port. Your computer picks a temporary port for its side, such as 52814. So one connection is the pair of sockets: 192.168.1.20:52814 ⇄ 203.0.113.10:443.

The TCP 3-Way Handshake 🤝

Before TCP sends any data, the two sides agree to talk. They swap three short messages. Each side also picks a starting sequence number (Module 1) for the bytes it will send. Real starting numbers are picked at random; we use round numbers here.

  • SYN means "synchronise": "Let's start, my numbers begin here."
  • ACK means "acknowledge": "I received everything up to here. Send byte number ___ next."
1. Client ➔ Server: [SYN] (Seq=1000) "Let's connect! My numbers start at 1000."
2. Server ➔ Client: [SYN-ACK] (Seq=5000, Ack=1001) "Got it! Mine start at 5000."
3. Client ➔ Server: [ACK] (Seq=1001, Ack=5001) "Agreed! The connection is open."

🧪 Watch it happen: open the Protocol Lab Studio and click Start Handshake to see SYN, SYN-ACK and ACK travel between two computers.

Worked example 1: following the numbers

After the handshake, the client sends a 500-byte homework file in one segment. What does the server's ACK say?

Client → Server  SYN         seq=1000
Server → Client  SYN-ACK     seq=5000 ack=1001
Client → Server  ACK         seq=1001 ack=5001
Client → Server  DATA 500 B  seq=1001
                 (bytes 1001 – 1500)
Server → Client  ACK         ack=1501
                 "Send byte 1501 next"

The ACK number is always the next byte the receiver expects: 1001 + 500 = 1501.

Worked example 2: a lost segment

The client sends four segments of 100 bytes. The third one is lost on the way.

seq=1001 (100 B) ──► arrives  → ACK 1101
seq=1101 (100 B) ──► arrives  → ACK 1201
seq=1201 (100 B) ──✘ lost
seq=1301 (100 B) ──► arrives  → ACK 1201
                                (still missing 1201!)
sender notices, resends:
seq=1201 (100 B) ──► arrives  → ACK 1401

The receiver keeps saying "I still need byte 1201". The sender resends it. Once the gap is filled, the receiver acknowledges everything up to byte 1400 in one go: ACK 1401. This is how TCP makes sure nothing is missing and everything is in order.

When the conversation is over, each side sends a FIN ("finished") message to close the connection politely.

TCP vs. UDP Breakdown

TCP (Transmission Control Protocol)

Opens a connection first. Checks that every byte arrives. Resends lost data. Puts data back in order. Its header is 20 to 60 bytes.

Best for: web pages, email, file downloads, online forms.

UDP (User Datagram Protocol)

No connection and no handshake. Just sends each message (called a datagram). No resending. Its header is only 8 bytes.

Best for: live video and voice calls, live online classes, quick DNS lookups.

Why would anyone choose UDP? In a live call, a sound that arrives half a second late is useless. It is better to skip it and play the next sound now. Waiting for a resend would make the call stutter.

DNS uses UDP for most questions because they are tiny and one reply is enough. It switches to TCP when an answer is too large. The newest web protocol, HTTP/3, also runs on UDP and adds its own checking on top (Module 6).

Worked Example 3: Seeing Your Own Connections 👀

The netstat command lists the connections your computer has open right now. On Windows, run:

netstat -an

Example output (shortened; yours will differ):

  Proto  Local Address        Foreign Address      State
  TCP    0.0.0.0:80           0.0.0.0:0            LISTENING
  TCP    192.168.1.20:52814   203.0.113.10:443     ESTABLISHED
  UDP    0.0.0.0:5353         *:*
  • LISTENING on port 80: a web server on this computer (for example XAMPP's Apache) is waiting for visitors.
  • ESTABLISHED: a finished handshake. Your browser (temporary port 52814) is talking to a secure website on port 443.
  • The UDP line has no state, because UDP has no connection.

On macOS and Linux, netstat -an also works. Many Linux systems use the newer ss -tuan instead.

Common Misunderstanding ⚠️

"UDP is just a broken version of TCP."

No. UDP is a deliberate choice. It skips the handshake and the resending to save time. For live voice, video and quick lookups, that is exactly what you want. Programs that need some checking can add their own on top of UDP, as HTTP/3 does.

"A port is a socket on the wall."

In this module, a port is not a physical hole. It is just a number in the TCP or UDP header that picks the right program.

🟢 Level 1: Recall

Put the three handshake messages in order: ACK, SYN, SYN-ACK. Then give the well-known port for HTTPS and for DNS.

Show answer
SYN, then SYN-ACK, then ACK. HTTPS uses port 443 and DNS uses port 53.

🟡 Level 2: Apply

After the handshake, a client's next byte is number 2001. It sends a 300-byte segment, then a 200-byte segment. Both arrive. What ACK number does the server send after each one?

Show answer
Segment 1: bytes 2001 – 2300 → ACK 2301
Segment 2: bytes 2301 – 2500 → ACK 2501

The ACK is always the next byte expected.

A community school is planning its online services. For each one, choose TCP or UDP and give a reason:

  1. Students upload their science project files.
  2. A teacher runs a live video class for students at home.
  3. A laptop looks up the address of the school's website by name.
  4. The office emails donation receipts to a charity's supporters.

Hint: ask "Must every byte arrive?" or "Is fresh data more important than complete data?"

Show one possible answer
  1. TCP. A file with a missing piece is broken, so every byte must arrive.
  2. UDP. Live sound and pictures must be fresh; a late frame is skipped, not waited for.
