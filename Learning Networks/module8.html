REST vs. WebSockets: When to Use Which

REST (Request / Response)

Client requests data, server responds and closes connection. Ideal for standard CRUD, form submissions, and database records.

WebSockets (Persistent Duplex)

Connection upgrades via 101 Switching Protocols and stays open indefinitely. Either side can send messages with only 2 bytes of overhead!

The Developer's Network Diagnostic Toolkit

# 1. Test ping and packet latency
ping cloudflare.com

# 2. Map every intermediate router hop across the globe
tracert oasis-aid.org (Windows) or traceroute (Linux/Mac)

# 3. Send custom HTTP requests with headers
curl -i -X GET https://api.oasis-aid.org/v1/relief-camps

# 4. View active open sockets and listening ports
netstat -ano (Windows) or ss -tulpn (Linux)

Mastering DevTools Network Waterfall

Open DevTools (F12) and click the Network tab. Inspect:

  • Queueing & Stalled: Browser waiting for available TCP connection slots.
  • DNS Lookup: Time spent translating the hostname into an IP address.
  • Initial Connection & SSL: TCP 3-way handshake + TLS 1.3 key exchange.
  • TTFB (Time to First Byte): Backend server calculation latency.
  • Content Download: Network bandwidth speed transferring the payload.
