DNS: The Global Phonebook 📖🔍

How human-friendly domain names like juniorcoders.org become machine-routable IP addresses in milliseconds.

Names for People, Numbers for Computers 📇

🧠 Real-life analogy: On your phone, you tap "Grandma" to call her. You do not type her number from memory. Your contacts list turns the name into the number for you. DNS (the Domain Name System) is the Internet's shared contacts list. It turns a name like library.example.org into an IP address like 203.0.113.25.

People remember names easily. Routers only understand IP addresses (Module 3). DNS connects the two. Your device asks a DNS question before almost every new website it visits.

Reading a Domain Name From Right to Left 🌳

A domain name is a list of labels separated by dots. The most general part is on the right. The most specific part is on the left.

library . example . org . (root)
   │         │        │      │
   │         │        │      └ the root: top of the tree
   │         │        └ TLD: top-level domain
   │         └ the domain someone registered
   └ subdomain: one part of that site

A TLD (top-level domain) is the last label, such as .org, .edu or a country code like .pk or .uk. The hidden dot at the very end stands for the root, the top of the whole naming tree.

The 5 Steps of a DNS Lookup

A recursive resolver is a helper server that does the searching for you. It is often run by your ISP, or it may be a public one such as 1.1.1.1. Your device asks it one question. The resolver asks the other servers, step by step, until it finds the answer.

1. Local cache: the browser and the computer check their memory first.
2. Recursive resolver: if there is no saved answer, your device asks the resolver.
3. Root server (.): points the resolver to the servers for the TLD (e.g. .org).
4. TLD server (.org): points to the domain's own authoritative server.
5. Authoritative server: gives the official answer, such as the A record (IPv4 address).

An authoritative server is the server that holds the official records for a domain. Its answer is the true one. There are 13 named root servers, and each is copied to many places around the world so that answers are fast everywhere.

Worked example 1: looking up library.example.org

Laptop   → Resolver : "library.example.org?"
Resolver → Root     : "library.example.org?"
Root     → Resolver : "Ask the .org servers"
Resolver → .org     : "library.example.org?"
.org     → Resolver : "Ask ns1.example.org"
Resolver → ns1      : "library.example.org?"
ns1      → Resolver : "A 203.0.113.25,
                       keep for 3600 s"
Resolver → Laptop   : "203.0.113.25"

The laptop asked just one question. The resolver did all the other work. It also saves the answer, so the next person who asks gets it straight away.

Essential DNS Record Types

A DNS record is one line of information stored for a name. Different types answer different questions.

A Record

Name ➔ IPv4 address (e.g. 203.0.113.25).

AAAA Record

Name ➔ IPv6 address (128-bit, e.g. 2001:db8::25).

CNAME Record

Canonical name: makes one name an alias (nickname) for another, e.g. www.example.org ➔ example.org.

MX Record

Mail exchanger: names the servers that receive email for the domain.

NS Record

Name server: lists the authoritative servers for the domain.

TXT Record

Free text. Often used to prove who owns a domain and to help stop fake emails.

Worked Example 2: Asking DNS Yourself 🔍

The nslookup command asks a DNS question from the command line. It works on Windows, macOS and Linux.

nslookup wikipedia.org

Example output (the shape is real; the addresses here are example values, and yours will differ):

Server:  router.home
Address:  192.168.1.1

Non-authoritative answer:
Name:    wikipedia.org
Addresses:  2001:db8::20
          203.0.113.20
  • Server and the first Address show which resolver answered. Here it is the home router, which passes questions on.
  • Non-authoritative answer means the answer came from a resolver, not straight from the domain's own server. That is normal.
  • The Addresses lines give the IPv6 (AAAA) and IPv4 (A) answers.

You can ask for one record type. For example, nslookup -type=mx example.org asks for mail servers.

Time To Live (TTL): Saving Answers ⏳

Every DNS record has a TTL (time to live), counted in seconds. It tells resolvers how long they may keep a saved copy, called a cache. A TTL of 3600 means "you may keep this for 1 hour". Caching saves many repeated questions and makes browsing faster.

Worked example 3: when does a change reach everyone?

A school's record has TTL 3600. A resolver saves it at 09:00. At 09:30, the school moves its website to a new IP address.

09:00  resolver saves old address (TTL 3600 s)
09:30  school changes the A record
09:30–10:00  resolver still gives the OLD address
10:00  saved copy expires
10:00+ next question fetches the NEW address

Some users may reach the old server for up to an hour. Careful admins lower the TTL (for example to 300 seconds) a day before a planned move.

Common Misunderstanding ⚠️

"DNS loads the website."

No. DNS only gives back an address. After that, your browser connects to that address (with TCP, from Module 4) and asks for the page. If DNS works but the page still fails, the problem is somewhere after DNS.

"A DNS change always takes 48 hours to spread."

The waiting time depends on the TTL of the old record. With a short TTL, most people see the change within minutes.

🔐 Amānah: Plain DNS questions are not secret. They show which sites a person visits. Newer browsers can use encrypted DNS (DNS over HTTPS) to keep these questions private. Treat people's browsing history as a trust.

🏆 Practice: three levels

🟢 Level 1: Recall

Which record type gives: (a) an IPv4 address, (b) an IPv6 address, (c) the mail servers for a domain?

Show answer
(a) A record, (b) AAAA record, (c) MX record.

🟡 Level 2: Apply

A resolver saves a record at 14:00:00 with TTL 300. (1) Until what time may it keep using that copy? (2) In the nslookup output in Worked example 2, which line is the IPv4 address?

Show answer
300 s = 5 minutes
14:00:00 + 5 min = 14:05:00

(1) Until 14:05:00. (2) 203.0.113.20 is the IPv4 address; 2001:db8::20 is the IPv6 one.

🔴 Level 3: Challenge

A neighbourhood library owns example.org. Plan its DNS records:

  1. The catalogue site library.example.org lives at IPv4 203.0.113.25 and IPv6 2001:db8::25.
  2. Visitors who type www.example.org should reach the same site.
  3. Email to the library should go to mail.example.org.
  4. The library will move servers next week. What should it do with the TTL today?
Show one possible answer
library.example.org  A      203.0.113.25
library.example.org  AAAA   2001:db8::25
www.example.org      CNAME  library.example.org
example.org          MX     10 mail.example.org

The 10 in the MX record is a priority number. When there are several mail servers, the lowest number is tried first.

Today, lower the TTL on the A and AAAA records (for example from 3600 to 300). After the move, saved copies expire within 5 minutes, so visitors quickly find the new server.
