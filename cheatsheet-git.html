🗂️ Git & GitHub Cheat Sheet

The Git commands you use every day, from your first commit to a pull request, in the same order as the textbook.

Where your work lives: three places on your computer, plus one online. Working tree (the files you edit) → git add → staging area → git commit → local repository → git push → remote on GitHub. Run git status often: it tells you where everything is and what to do next.
⚙️ Setup & Configuration
git --versionCheck that Git is installed
git config --global user.name "Amina Khan"Your name on every commit
git config --global user.email "student@example.com"Your email on every commit
git config --global init.defaultBranch mainNew repos start on main
git config --listShow your settings
📁 Starting & Status
git initStart a repo in the current folder
git clone <url>Copy a GitHub repo to your computer
git statusWhat is changed, staged or untracked?
git log --onelineShort history, one commit per line
git log --oneline --graph --allHistory drawn as a branch tree
git log -pHistory with each commit's changes
git show <commit-id>One commit's message and changes
💾 Staging & Commits
git add index.htmlStage one file for the next commit
git add .Stage all new, changed and deleted files in this folder
git diffChanges not staged yet
git diff --stagedChanges that will go into the commit
git commit -m "feat: add contact form"Save the staged changes as a snapshot
git commit --amend -m "new message"Replace the last commit (also adds anything staged). Only before you push!
🛡️ .gitignore
.envOne line per file Git must never track
*.logEvery file ending in .log
node_modules/A whole folder
git rm --cached .envStop tracking a file already committed (keeps your copy)
🛟 Undoing & Safety Nets
git restore <file>Throw away unsaved edits in a file (cannot be undone)
git restore --staged <file>Unstage a file; your edits stay
git reset --soft HEAD~1Undo the last commit, keep its changes staged (before pushing)
git revert <commit-id>Undo a pushed commit with a new commit (safe)
git stashPut unfinished work aside
git stash listSee what is put aside
git stash popBring the latest stash back
🌿 Branching & Switching
git branchList local branches (* = current)
git branch -aLocal and remote branches
git switch -c feature/dark-modeCreate a branch and move to it
git switch mainMove back to main
git merge feature/dark-modeBring that branch into the current one
git branch -d feature/dark-modeDelete a merged branch
🧩 Merge Conflicts
<<<<<<< HEADStart of your branch's version
=======Line between the two versions
>>>>>>> featureEnd of the other branch's version
(edit the file)Keep the right text, delete all three marker lines
git add <file> then git commitMark it fixed and finish the merge
git merge --abortCancel the merge and go back to before it
☁️ Remotes & GitHub
git remote add origin <url>Link your repo to a GitHub repo
git remote -vShow the linked addresses
git push -u origin mainFirst push; remembers where to push
git pushSend new commits (after the first -u push)
git fetchDownload new commits without merging
git pullFetch + merge into your branch (do it before you start work)
🤝 Pull Requests
Fork (on GitHub)Your own copy of someone else's repo
git switch -c fix/typoDo each change on its own branch
git push -u origin fix/typoSend the branch to GitHub
Compare & pull requestAsk the owner to review and merge it
Fixes #12In the PR text: closes issue 12 when merged
Amānah (trust) rule: never commit passwords, API keys or .env files. Add them to .gitignore before your first git add .. If a secret was pushed, removing the file is not enough: change the password or key at once. Write commit messages that honestly say what changed.
