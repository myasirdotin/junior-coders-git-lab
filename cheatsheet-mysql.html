🗄️ MySQL Cheat Sheet

The SQL you use most, written on the textbook's school_db: classes, students, books, loans and donations.

SQL basics: a statement reads like a sentence (SELECT name FROM students WHERE grade = 8;) and ends with ;. Keywords are written in UPPERCASE by habit, text values go in 'single quotes', numbers do not. Practise these queries in the SQL Sandbox or in phpMyAdmin.
🗄️ Database Commands

A database is a container for related tables, like one cupboard for all the school's records. You create it once, then USE it so every command works inside it. DROP deletes for good, so check the name and keep a backup first.

CREATE DATABASE IF NOT EXISTS school_db CHARACTER SET utf8mb4;Make a database (utf8mb4 stores every language)
USE school_db;Work inside this database
SELECT DATABASE();Which database is active?
SHOW DATABASES;   SHOW TABLES;List databases / tables
DESCRIBE students;Show a table's columns and types
DROP TABLE IF EXISTS old_table;Delete a table and its rows (no undo)
TRUNCATE TABLE old_table;Empty a table but keep its columns
DROP DATABASE IF EXISTS practice_db;Delete a whole database (back up first!)

🏗️ CREATE TABLE

CREATE TABLE sets the plan of a table: its columns, the type of value each column holds, and its rules. The right type keeps data correct, for example DECIMAL for exact amounts. Rules like NOT NULL stop missing or wrong data from getting in.

CREATE TABLE classes (
  id INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  teacher VARCHAR(50) NOT NULL
);
INTWhole number (grade, pages)
VARCHAR(100)Text up to 100 characters
TEXTLong text (a description)
DECIMAL(3,2)Exact decimal: 3 digits, 2 after the point (3.95)
BOOLEANTRUE (1) or FALSE (0)
DATE   DATETIME'2026-09-02' / date + time
AUTO_INCREMENTMySQL numbers new rows 1, 2, 3...
NOT NULLA value is required
DEFAULT 'No'Used when no value is given

🔧 Change a Table

ALTER TABLE changes the plan of a table that already exists, without deleting its rows. Use it when a new need appears, such as an author column for books. Dropping a column also deletes all the data in it, so check before you run it.

ALTER TABLE books ADD COLUMN author VARCHAR(80);Add a column
ALTER TABLE books MODIFY pages SMALLINT;Change a column's type
ALTER TABLE books CHANGE pages page_count INT;Rename a column (give its type again)
ALTER TABLE books DROP COLUMN author;Remove a column and its data
RENAME TABLE classes TO school_classes;Rename a table

🔍 SELECT (Read)

SELECT reads data without changing it, so it is always safe to try. Name the columns you need, then use WHERE to keep only the matching rows. ORDER BY sorts the result, and LIMIT shows a few rows at a time, like pages.

SELECT * FROM students;Every row and column
SELECT name, gpa FROM students;Only some columns
SELECT DISTINCT city FROM students;Each city once
WHERE grade = 8Rows that match
WHERE gpa >= 3.5 AND city = 'Lahore'Both must be true (OR: either)
WHERE grade <> 9Not equal (also !=)
WHERE title LIKE 'Clean%'Starts with "Clean" (% = any text)
WHERE title LIKE '%code%'Contains "code"
WHERE city IN ('Lahore', 'Karachi')Matches any value in the list
WHERE pages BETWEEN 200 AND 300A range (both ends included)
WHERE city IS NULL   IS NOT NULLEmpty / not empty (never = NULL)
ORDER BY gpa DESC, name ASCSort: highest GPA first, then A→Z
LIMIT 3   LIMIT 3 OFFSET 3First 3 rows / skip 3, then 3 (page 2)

✏️ INSERT / UPDATE / DELETE

These commands change data: INSERT adds rows, UPDATE changes them and DELETE removes them. Without WHERE, UPDATE and DELETE affect every row in the table. A transaction groups changes so they all succeed together or can all be undone.

INSERT INTO students (name, grade, class_id) VALUES ('Yusuf', 8, 2);Add one row (list the columns)
INSERT INTO books (title, pages) VALUES ('Tafsir Notes', 150), ('Garden Guide', 96);Add several rows at once
UPDATE books SET available = 'Yes' WHERE id = 3;Change a value (always with WHERE)
UPDATE loans SET returned = 'Yes' WHERE id = 2;Mark a library loan as returned
DELETE FROM loans WHERE id = 10;Delete one row (always with WHERE)
SELECT * FROM loans WHERE id = 10;Run the same WHERE as a SELECT first
START TRANSACTION; ... COMMIT;Keep several changes together
ROLLBACK;Undo the changes since START TRANSACTION

📊 Aggregate Functions

Aggregate functions turn many rows into one answer, such as a count, a total or an average. GROUP BY gives one answer per group, like one total per charity cause. WHERE filters rows before grouping; HAVING filters the groups afterwards.

COUNT(*)Number of rows
COUNT(city)Rows where city is not NULL
COUNT(DISTINCT city)Number of different cities
SUM(amount)   AVG(gpa)Total / average
MAX(gpa)   MIN(pages)Largest / smallest
SELECT cause, SUM(amount) AS total FROM donations GROUP BY cause;One total per charity cause
HAVING SUM(amount) > 2000Filter groups (WHERE filters rows first)
ROUND(AVG(gpa), 2)Round to 2 decimal places

🔗 JOINs

Related data is kept in separate tables, linked by an id, so nothing is typed twice. A JOIN puts those tables back together in one result. INNER JOIN keeps only matching rows; LEFT JOIN keeps every row of the first table, even without a match.

INNER JOINOnly rows that match in both tables
LEFT JOINEvery row of the left table, NULL where no match
RIGHT JOINEvery row of the right table
SELECT s.name, c.name AS class
FROM students s
INNER JOIN classes c ON s.class_id = c.id;
SELECT s.name, COUNT(l.id) AS loans
FROM students s
LEFT JOIN loans l ON l.student_id = s.id
GROUP BY s.id, s.name;
ON l.student_id = s.idHow the rows are matched
students s   s.nameShort alias; prefix columns to avoid mix-ups

🪆 Subqueries

A subquery is a SELECT inside another query, written in brackets. It answers a smaller question first, such as the average GPA, and the outer query uses that answer. Use one when you would otherwise run two queries and copy a value across by hand.

SELECT name FROM students WHERE gpa > (SELECT AVG(gpa) FROM students);Students above the average GPA
SELECT title FROM books WHERE id IN (SELECT book_id FROM loans WHERE returned = 'No');Books that are out on loan now
(SELECT ...)The inner query runs first; its answer feeds the outer one

🔑 Keys & Constraints

A primary key gives each row its own id. A foreign key points to a row in another table, so a student cannot join a class that does not exist. Constraints are rules MySQL checks on every change, which keeps your data correct.

id INT AUTO_INCREMENT PRIMARY KEYUnique ID for each row (one per table)
FOREIGN KEY (class_id) REFERENCES classes(id)Must point to a real class
ON DELETE SET NULLParent deleted → link becomes NULL
ON DELETE CASCADEParent deleted → child rows deleted too
UNIQUE (email)No two rows with the same value
CHECK (amount > 0)Value must pass a rule
CREATE INDEX idx_city ON students(city);Faster searches on a column

💡 Useful Extras

Built-in functions tidy results as you read them: join text, change letter case, replace NULL with a word, or work with dates. They change only what is shown, not what is stored. When the SQL comes from PHP, always send values through a prepared statement.

SELECT CONCAT(name, ' (', city, ')') AS label FROM students;Join text into one column
UPPER(name)   LOWER(name)   LENGTH(name)UPPERCASE, lowercase, length
COALESCE(city, 'Unknown')First value that is not NULL (also IFNULL)
NOW()   CURDATE()Date + time now / today's date
WHERE YEAR(loan_date) = 2026Filter by the year of a date
DATEDIFF(CURDATE(), loan_date)Days since the loan
-- commentOne-line comment (space after --)
$pdo->prepare("... WHERE id = ?")From PHP: always a prepared statement
