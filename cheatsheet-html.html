🌐 HTML Cheat Sheet

Every tag you need on one page: the left column shows the code, the right column says what it does.

Golden rule: choose tags for what the content means, not how it looks. Headings are <h1>–<h6>, important words are <strong>, and every image gets alt text. Use one <h1> per page for its main title, and let CSS do the styling.
🏗️ Document Structure

Every web page has the same skeleton. The <head> holds facts about the page for the browser. The <body> holds everything people see. Start each new page from this skeleton so nothing is missing.

<!DOCTYPE html>First line: "this is a modern HTML page"
<html lang="en">Wraps the whole page; lang tells screen readers the language
<head>Information about the page (not shown on it)
<meta charset="UTF-8">Shows every letter and language correctly
<meta name="viewport" content="width=device-width, initial-scale=1">Makes the page fit phone screens
<title>My Library</title>Text on the browser tab
<link rel="stylesheet" href="style.css">Connects a CSS file (inside <head>)
<body>Everything visible on the page goes here
<script src="app.js"></script>Connects a JavaScript file (just before </body>)

✏️ Headings & Text

Headings and paragraphs give your page an outline, like chapters in a book. Choose tags for their meaning, not their looks. <strong> says "this is important". CSS decides how big or bold things look.

<h1> … <h6>Headings: h1 is the main title, h6 the smallest; do not skip levels
<p>A paragraph of text
<strong>Important words (shown bold)
<em>Stressed words (shown italic)
<b> / <i>Bold or italic look only, with no extra meaning
<br>Line break inside a paragraph (no closing tag)
<hr>A dividing line between topics
<mark>Highlighted text, like a marker pen
<code>Computer code inside a sentence, like this
<small>Fine print, such as a copyright line
<del>Deleted text (crossed out)
<sup> / <sub>x2 and H2O
<blockquote>A longer quote from another source

🔗 Links, Images & Media

Links join pages together, and href says where a link goes. Images, video and sound come from separate files named by src. Always describe an image with alt, so people who cannot see it still know what it shows.

<a href="about.html">About</a>A link; the words inside are what people click
target="_blank"Opens the link in a new tab
<img src="logo.png" alt="School logo">Shows an image (no closing tag)
alt="School logo"Read aloud by screen readers and shown if the image fails. Always add it (alt="" only for decoration)
width="200" height="100"Image size in pixels (stops the page jumping while it loads)
<figure> + <figcaption>An image with its caption
<video src="talk.mp4" controls>A video player; controls adds the play and volume buttons
<audio src="recitation.mp3" controls>An audio player (without controls nothing is shown)
<iframe src="map.html" title="School map">Shows another page inside yours; title says what it is

📝 Lists

Lists put items in a neat group. Use a numbered list when the order matters, like the steps of a recipe. Use a bullet list when it does not, like a shopping list. Every item goes in its own <li> tag.

<ul>Bullet list (order does not matter)
<ol>Numbered list (1, 2, 3 …)
<li>One item inside <ul> or <ol>
<dl>Description list, like a glossary
<dt>The word being explained
<dd>Its explanation

📖 Learn more: Chapter 10: Lists

📊 Tables

A table shows data in rows and columns, like a class timetable. You build it one row at a time, and each row holds its cells. Use tables only for data, never to arrange the parts of a page.

<table>A table of data (not for page layout)
<caption>The table's title
<thead> / <tbody> / <tfoot>Heading rows, data rows, total rows
<tr>One table row
<th>A heading cell that names a column or row
<th scope="col">Tells screen readers the heading is for its column ("row" for a row)
<td>One data cell
colspan="2"The cell covers 2 columns
rowspan="2"The cell covers 2 rows

📬 Forms

A form collects answers from people, such as a library sign-up. Every input needs a label, so everyone knows what to type. The name on an input labels the answer that is sent. Only ask for what you really need.

<form action="save.php" method="post">Holds the inputs; says where and how to send them
<label for="email">Email</label>Names an input; for matches the input's id
<input id="email" name="email">name labels the data that is sent; an input without it is not sent
<input type="text">One-line text box
<input type="email">Checks the text looks like an email
<input type="password">Hides the letters as you type
<input type="number">Numbers only, with up/down arrows
<input type="checkbox">Tick box: choose any number
<input type="radio" name="grade">Choose one; radios with the same name form a group
<select> + <option>A drop-down list and its choices
<textarea>Text box for several lines
<button type="submit">Send</button>Sends the form
placeholder="e.g. Amina"Grey example text (it does not replace a label)
requiredThe form will not send until this is filled in

🧠 Semantic Tags

Semantic means "with meaning". These tags tell browsers, search engines and screen readers what each part of the page is for. Use them first. Use <div> or <span> only when no meaningful tag fits.

<header>Top part: logo, title, menu
<nav>A block of menu links
<main>The main content (one per page)
<section>A group of content on one topic, with a heading
<article>Content that makes sense on its own, like a news item
<aside>Extra content beside the main text
<footer>Bottom part: contact, copyright, links
<div>A box with no meaning, for grouping and styling
<span>An inline wrapper with no meaning

⚙️ Common Attributes

An attribute is extra information inside an opening tag, written as name="value". It changes or describes the element. Some work on almost any tag, like class and id. CSS and JavaScript use them to find elements.

class="card"A group name for CSS; many elements can share it
id="contact"A unique name, used once per page
style="color: green"CSS on one element (better: use a CSS file)
href="url"Where a link goes
src="file"The file to load (image, video, script)
alt="text"Words that describe an image
title="hint"Small hint shown when the mouse rests on it
disabledThe input cannot be used and is not sent
hiddenHides the element
data-book-id="42"Your own extra data on an element (data- + any name)

💬 Comments & Entities

A comment is a note for people who read your code; the browser skips it. An entity is a short code for a character HTML would read as part of a tag, like <. It starts with & and ends with ;.

<!-- note -->A comment: a note for people, not shown on the page
&lt; &gt;Shows < and > as text instead of a tag
&amp;Shows the & sign
&copy;Shows the © sign
&nbsp;A space that keeps two words on one line

Amānah (trust) rule: make your page usable by everyone. Write real alt text, connect every input to a <label>, and ask in a form only for the information you really need.
