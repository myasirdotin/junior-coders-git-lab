Level 1

Passwords, Entropy & Multi-Factor Auth 🔑🔐

Why long passwords beat short tricky ones, how websites should store passwords, and how a second step (MFA) keeps you safe.

🚲 Think of a Bike Lock

🧠 Real-life analogy: A bike lock with 3 number wheels has 1,000 possible codes (000 to 999). A patient thief could try them all in an afternoon.

Add one more wheel and there are 10,000 codes. Add six more and there are 1,000,000,000 codes. Each extra wheel makes guessing ten times harder.

Passwords work the same way. Every extra character multiplies the work for a guesser.

Attackers rarely guess by hand. They use computers that can try billions of guesses per second. So a good password must be long and unpredictable.

🎲 Entropy: Measuring Unpredictability

Entropy measures how hard something is to guess. We count it in bits. Each extra bit doubles the number of guesses an attacker needs.

Entropy (bits) = Length × log2(PoolSize)

PoolSize = how many different symbols
           each character could be
  Digits only (0–9)           → 10
  Lowercase letters (a–z)     → 26
  Every keyboard character    → 95

log2(PoolSize) = how many times you double 1
                 to reach the pool size
  log2(10) ≈ 3.32
  log2(26) ≈ 4.70
  log2(95) ≈ 6.57
⚠️ This formula only works when every character is picked at random. A password like Password1! looks mixed, but it is on every guessing list. Its real entropy is very low.

🧮 Worked Example 1: Comparing Three Passwords

Let us use the formula on three random passwords.

A) 4-digit PIN, e.g. 4071
   4 × 3.32 = about 13 bits
   (10,000 possible PINs: very weak)

B) 8 random keyboard characters, e.g. Tr$8!kQ2
   8 × 6.57 = about 53 bits
   (strong-ish, but hard to remember)

C) 16 random lowercase letters
   16 × 4.70 = about 75 bits
   (much stronger, only small letters!)

What this shows: password C uses only small letters. It is still far stronger than B, because it is twice as long. Length beats tricky symbols.

📝 Worked Example 2: The Passphrase

Random letters are hard to remember. A passphrase solves this. It is a few random words joined together, like this made-up example:

maple-lantern-orbit-pebble-harvest

Suppose each word is picked at random from a list of 7,776 words. Each word adds about 12.9 bits.

4 random words: 4 × 12.9 ≈ 52 bits
5 random words: 5 × 12.9 ≈ 65 bits
6 random words: 6 × 12.9 ≈ 78 bits
  • The words must be random. A famous saying or song line is easy to guess.
  • Five or six words are better than four for important accounts.
  • Never use an example passphrase from a website, including this one. Everyone has seen it.

🗄️ Worked Example 3: How Websites Should Store Passwords (Amānah)

A website must never keep your real password. If its database is stolen, every password would leak. Instead, it keeps a hash.

  • Hash: a scrambled "fingerprint" of the password. You can make the fingerprint from the password. You cannot turn the fingerprint back into the password.
  • Salt: a random bit of extra text added to each password before hashing. Two people with the same password get different hashes. This spoils attackers' ready-made lists of hashes.
  • Slow hashing: good password hashes, such as bcrypt and Argon2id, are built to be slow. One login barely notices. An attacker trying billions of guesses is slowed down hugely.

Here is a weak way and a safe way in PHP. Read the comments: they explain each line.

<?php
// ❌ UNSAFE: the real password is saved as plain text.
// Anyone who steals the database can read it.
$saved = $password;

// ✅ SAFE: PHP adds a random salt and makes a slow hash.
$saved = password_hash($password, PASSWORD_DEFAULT);
// $saved now looks like: $2y$...  (a long scrambled string)

// Later, when the user logs in:
if (password_verify($typedPassword, $saved)) {
    echo "Welcome back!";
} else {
    echo "Wrong password.";
}
?>

The fix explained: password_hash() does the salting and slow hashing for you. password_verify() checks a typed password against the saved hash. The real password is never stored. If the server supports it, PASSWORD_ARGON2ID can be used instead of PASSWORD_DEFAULT.

📱 Multi-Factor Authentication (MFA)

Authentication means proving who you are. Multi-factor authentication (MFA) asks for proof from more than one of these groups:

1. Something you know
A password or passphrase.
2. Something you have
Your phone, or a small USB security key.
3. Something you are
Your fingerprint or face.

Using exactly two of these is called 2FA (two-factor authentication). It is the most common kind of MFA.

Not all second steps are equally strong:

  1. Strongest: passkeys and security keys. They only work on the real website, so a fake site cannot trick them.
  2. Good: an authenticator app. It shows a 6-digit code that changes every 30 seconds.
  3. Better than nothing: a code sent by text message (SMS).
💡 Story: Aisha's password leaked from an old quiz website. A stranger tried it on her school email. Her phone asked, "Is this you signing in?" She tapped No. MFA stopped the stranger. Then she changed her password.

✅ What To Do: Your Password Checklist

  • ☐ Use a passphrase of 5 or more random words, or a long random password.
  • ☐ Use a different password for every account. One leak should not open everything.
  • ☐ Let a password manager remember them. It is an app that stores your passwords in a locked vault.
  • ☐ Turn on MFA, starting with your email account.
  • ☐ Never tell anyone your MFA code. Real companies and schools never ask for it.
  • ☐ If a site says your password leaked, change it straight away.
