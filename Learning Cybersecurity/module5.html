Database Defense: Defeating SQLi 💉🗄️

Guarding the data vault. Discover how query concatenation creates vulnerabilities and how Prepared Statements eliminate them.

How SQL Injection Works

When user input is directly glued into an SQL command string, special characters like single quotes ' allow an attacker to escape the data field and inject new SQL instructions:

// Vulnerable query template:
$sql = "SELECT * FROM users WHERE user = '$username' AND pass = '$password'";

// Attacker inputs username: admin' OR '1'='1' --

// Constructed SQL command executed by database:
SELECT * FROM users WHERE user = 'admin' OR '1'='1' --' AND pass = '...'
(The '--' comments out the password check! The attacker is logged in as admin!)

The Silver Bullet: Prepared Statements (PDO)

Prepared statements separate the SQL command structure from the user data. The database compiles the SQL logic first, ensuring user input is strictly treated as inert literal values:

// ✅ 100% SECURE: Prepared Statement in PHP PDO
$stmt = $pdo->prepare("SELECT id, password_hash FROM users WHERE username = :user");

// Safely bind the parameter (immune to injection!)
$stmt->execute([':user' => $_POST['username']]);
$row = $stmt->fetch();

if ($row && password_verify($_POST['password'], $row['password_hash'])) {
    // Welcome authorized user!
}

The Three Database Security Rules (*Iḥsān*)

  1. 100% Parameterization: Never concatenate variables into SQL strings. Use prepared statements for every query.
  2. Principle of Least Privilege: The database account used by your web server should never have `DROP DATABASE` or superuser privileges.
  3. Never Expose Raw DB Errors: Catch PDO exceptions and log them internally. Never output raw database error messages to public web users!
