Cybersecurity Best Practices 🛡️✨

Engineering systems with rigorous defense in depth, zero-trust architecture, and sacred stewardship (*Amānah* & *Iḥsān*).

1. 100% Prepared Statements for Every Database Interaction

Never concatenate raw strings or untrusted variables into SQL statements. Parameter binding completely segregates SQL code logic from data input.

✅ Good: $stmt = $pdo->prepare("SELECT id FROM users WHERE email = ?"); $stmt->execute([$email]);
❌ Bad: $db->query("SELECT id FROM users WHERE email = '$email'"); // Vulnerable to SQLi

2. Contextual Output Encoding for Every Rendered Variable

Input sanitization alone is insufficient; context matters. Always encode special HTML characters before rendering dynamic variables to prevent stored and reflected XSS.

✅ Good: <span><?= htmlspecialchars($name, ENT_QUOTES, 'UTF-8') ?></span>
❌ Bad: <span><?= $name ?></span> // Direct execution of script payloads

3. Use Modern Adaptive Key Derivation for Password Storage

Never use fast general-purpose hashes (MD5, SHA-1, raw SHA-256) for passwords. Employ slow, salted, memory-hard algorithms such as Argon2id or bcrypt.

✅ Good: $hash = password_hash($password, PASSWORD_ARGON2ID); // Salt & work factor included
❌ Bad: $hash = hash('sha256', $password); // Crackable at billions of guesses/sec on GPUs

4. Fortify Session Cookies with Triple Defense Flags

Set HttpOnly to stop JavaScript theft, Secure to guarantee transit over TLS, and SameSite=Strict to prevent CSRF attacks.

✅ Good: Set-Cookie: sid=abc123xyz; Secure; HttpOnly; SameSite=Strict; Path=/
❌ Bad: Set-Cookie: sid=abc123xyz; Path=/ // Readable via document.cookie

5. Strip Image EXIF Metadata Before Storage (*Ḥayā'* & Privacy)

User uploads frequently harbor GPS coordinates, home addresses, camera models, and timestamps. Always re-encode or strip EXIF metadata immediately upon receipt.

✅ Good: Re-encode image through GD/Imagick or run exif_read_data / strip metadata before saving.
❌ Bad: Saving raw user smartphone camera photos directly to a public media bucket.

6. Practice the 3-2-1 Backup Rule for System Resiliency

Maintain at least 3 total copies of critical data, on 2 distinct media types, with 1 copy stored securely offsite and offline (immutable air-gap against ransomware).

✅ Good: Primary DB + Local encrypted NAS backup + Encrypted off-site cloud storage.
❌ Bad: Database running without automated snapshots or stored on the same virtual disk.

7. Adopt the Principle of Least Privilege (PoLP)

Web applications should never connect to databases using the `root` administrative account. Create a dedicated application user granted only `SELECT`, `INSERT`, `UPDATE`, and `DELETE` on specific tables.

✅ Good: GRANT SELECT, INSERT, UPDATE ON portal_db.* TO 'web_app'@'localhost';
❌ Bad: GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION;
