Level 3

Cryptography & Secure Channels 🔐📡

Learn the difference between encoding, encryption and hashing, and stay safe on public Wi-Fi.

📦 Three Ways to Change a Message

🧠 Real-life analogy: imagine three things you could do to a note.

  • Write it in Morse code. It looks different, but anyone with a Morse chart can read it. No secret is needed. This is like encoding.
  • Lock it in a box. Only someone with the key can open it and read the note. This is like encryption.
  • Blend fruit into a smoothie. You can always make the same smoothie from the same fruit. But you can never turn the smoothie back into fruit. This is like hashing.

Cryptography is the science of protecting information with mathematics. It helps all three CIA pillars from Module 1, but mostly secrecy and accuracy.

🔍 Encoding vs. Encryption vs. Hashing

1. Encoding (e.g. Base64)

Changes the format of data so it can travel safely, for example inside an email. It is not security. Anyone can reverse it without a key.

2. Encryption (e.g. AES)

Scrambles data so only key holders can read it. It can be reversed with the right key.

3. Hashing (e.g. SHA-256)

Makes a fixed-size "fingerprint" of data. It is one-way. You cannot turn a hash back into the original.

🧪 Worked Example 1: Encoding Is Not a Secret

Base64 is a common encoding. Here is the word "Salam" in Base64:

"Salam"  ──Base64──▶  U2FsYW0=
U2FsYW0= ──decode──▶  "Salam"   (no key needed!)

In JavaScript you can try it yourself with btoa("Salam") and atob("U2FsYW0=").

⚠️ Common mistake: a website stores passwords in Base64 and calls them "encrypted". They are not. Anyone who sees them can decode them in a second. Passwords need slow, salted hashing (Module 2).

🔑 Worked Example 2: Two Kinds of Encryption

An encryption key is a long secret number used to lock and unlock data.

  • Symmetric encryption (e.g. AES) uses one key to lock and unlock. It is very fast. The problem: both people need the same key, and sharing it safely is hard.
  • Asymmetric encryption uses a pair of keys. The public key can be shared with everyone. The private key stays secret with its owner.

🧠 Padlock analogy: Fatima hands out open padlocks to anyone (her public key). You put a letter in a box and snap her padlock shut. Now only Fatima can open it, because only she has the key (her private key).

Websites use both. Asymmetric keys help two computers agree on a shared secret. Then fast symmetric encryption protects the rest of the conversation.

🌊 Worked Example 3: The Avalanche Effect

A good hash changes completely when the input changes even a little. On average, about half of the output bits flip. This is called the avalanche effect. Here are the real SHA-256 hashes of two words (shortened):

"Salam"   ➔ e6aff8d7aabcab5ae8243568...
"Salam!"  ➔ df5531cc965daf33d93cd2fa...
One "!" added → a totally different fingerprint.

Where hashes help:

  • Checking downloads: a software site lists the SHA-256 hash of its file. You hash your download and compare. If they match, the file was not changed on the way (Integrity).
  • Passwords: websites store a hash, not the password. But SHA-256 is very fast, which helps guessers. For passwords, use slow, salted hashes like bcrypt or Argon2id (Module 2).

🔒 HTTPS and TLS: The Secure Channel

When you visit a website, your data hops through many computers on the way. Without protection, any of them could read it.

  • HTTPS is the secure version of the web's language, HTTP. The "S" stands for "secure".
  • TLS (Transport Layer Security) is the set of rules that makes HTTPS secure. Your browser and the website agree on secret keys, then encrypt everything they send. TLS 1.3 is the current version.
  • A certificate is the website's digital ID card. It proves the site really owns its name, for example greenfield-school.org.
⚠️ The padlock 🔒 means the connection is private. It does not mean the site is honest. A phishing site can have a padlock too (Module 3). Always check the domain name.

📶 Public Wi-Fi and VPNs

Free Wi-Fi in a library, airport or café is shared with strangers. Two risks to know:

  • Eavesdropping: on an open network, others nearby may see traffic that is not encrypted.
  • Evil twin: someone sets up a fake hotspot with a real-looking name, like "City Library Free WiFi". Devices that join it send their traffic through the faker.

A VPN (Virtual Private Network) builds an encrypted tunnel from your device to the VPN company. People on the local Wi-Fi then cannot see which sites you visit. But the VPN company can, so only use a trusted one, such as one your school or family approves.

✅ What To Do: Your Secure Channel Checklist

  • ☐ Look for https:// and the correct domain before typing a password.
  • ☐ If your browser warns "Your connection is not private", stop. Do not continue.
  • ☐ On public Wi-Fi, ask staff for the exact network name. Avoid logging in to important accounts.
  • ☐ Use mobile data or a trusted network for anything private.
  • ☐ Remember: encoding is not encryption. Never "hide" secrets with Base64.
  • ☐ As a builder: serve your sites over HTTPS, and hash passwords with password_hash().

🏆 Practice: three levels

🟢 Level 1: Recall

Which of the three (encoding, encryption, hashing) is one-way? Which needs a key to reverse? Which needs no secret at all?

Show answer
Hashing is one-way. Encryption needs a key to reverse. Encoding needs no secret, so anyone can reverse it.

🟡 Level 2: Apply

Choose encoding, encryption or hashing for each job, and say why.

  1. Storing student passwords on the school server.
  2. Sending a private message that the receiver must read.
  3. Checking that a downloaded science app was not changed.
  4. A friend stores a secret as btoa("myPin1234"). Is it safe?
Show answer
  1. Hashing, slow and salted: password_hash($password, PASSWORD_DEFAULT). Nobody needs to read the password back.
  2. Encryption, because the receiver must unlock and read it.
  3. Hashing: compare the file's SHA-256 with the one the publisher lists.
  4. Not safe. btoa is Base64 encoding; atob reverses it instantly.
