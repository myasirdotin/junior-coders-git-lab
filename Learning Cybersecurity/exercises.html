Tier 1 • Exercise 1

The CIA Triad Classification

Categorize the following three security incidents into Confidentiality, Integrity, or Availability:

  1. A DDoS attack floods a school web server with junk traffic, taking it offline during exams.
  2. An unauthenticated visitor reads confidential donor names and private phone numbers from an API.
  3. An attacker modifies the account balance in a charity database from $10 to $10,000.
View Solution 
1. DDoS taking server offline ➔ Availability failure
2. Unauthorized reading of donor names ➔ Confidentiality breach
3. Tampering with account balances ➔ Integrity compromise
Tier 1 • Exercise 2

Encoding vs. Encryption vs. Hashing

Which transformation should you use for: (a) Storing a user's password, (b) Sending binary image data over a JSON REST API, and (c) Sending a confidential message across public Wi-Fi?

View Solution 
(a) Storing a password ➔ Cryptographic Salted Hashing (Argon2id / bcrypt)
(b) Sending binary image data in JSON ➔ Encoding (Base64)
(c) Sending a confidential message over Wi-Fi ➔ Encryption (AES-256 / TLS 1.3)

🟡 Tier 2: Application & Modification

Refactoring vulnerable code and parameterizing queries.

Tier 2 • Exercise 3

Refactoring Vulnerable SQL to PDO Prepared Statements

Refactor this dangerous PHP code into a secure Prepared Statement that is immune to SQL injection:

// Vulnerable Code:
$email = $_POST['email'];
$query = "SELECT * FROM donors WHERE email = '" . $email . "'";
$res = $db->query($query);
View Solution 
// Secure Refactored Code:
$stmt = $pdo->prepare("SELECT * FROM donors WHERE email = :email");
$stmt->execute([':email' => $_POST['email']]);
$donor = $stmt->fetch();
Tier 2 • Exercise 4

XSS Output Sanitization in PHP & JavaScript

Explain how to safely render a user-submitted greeting in both PHP (server-side) and vanilla JavaScript (DOM client-side).

View Solution 
// In PHP:
echo htmlspecialchars($greeting, ENT_QUOTES, 'UTF-8');

// In JavaScript DOM:
const greetingDiv = document.getElementById('greeting');
greetingDiv.textContent = greeting; // (Never assign raw user data to innerHTML!)

🔴 Tier 3: Independent Security Architecture

Designing defense-in-depth protection and solving authorization flaws.

Tier 3 • Exercise 5

Hardening an Online Exam Submission Endpoint

Design the complete security checklist for a student exam submission form: protect against CSRF, rate-limit brute force submissions, validate file mime-types, and enforce ownership to prevent IDOR viewing of other students' exams.

View Solution 
1. CSRF Defense: Include a cryptographically random session token in the form.
2. HTTP Method: Use POST only with SameSite=Strict cookies.
3. Access Control (IDOR): Check $_SESSION['student_id'] against the exam record.
4. Input & File Validation: Verify file extension, check real MIME-type (finfo),
   and re-encode file names (never use original user filename).
5. Rate Limiting: Restrict submission attempts to 5 per minute per IP.
6. Headers: Inject Content-Security-Policy, HSTS, and X-Content-Type-Options: nosniff.
