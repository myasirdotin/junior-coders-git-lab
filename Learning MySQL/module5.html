Why Do We Need Multiple Tables?

Imagine you're building a school system. You could put everything into one giant table — but that creates a mess. What if a student has grades in 5 subjects? You'd need 5 rows for the same student!

The better approach is to split data into separate tables and then link them together. This is called a Relational Database — it's the whole reason MySQL is called "relational"!

students
id name
1 Ali Hassan
2 Sara Khan
3 Aisha Malik
🔗
grades
id student_id subject score
1 1 Math 95
2 1 Science 88
3 2 Math 99
4 3 English 78

The student_id column in the grades table is a Foreign Key — it points back to the id column in the students table. This is how the two tables are linked!

Creating These Tables

CREATE TABLE students ( id INT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100) ); CREATE TABLE grades ( id INT AUTO_INCREMENT PRIMARY KEY, student_id INT, -- Foreign Key: links to students.id subject VARCHAR(100), score INT ); -- Insert sample data INSERT INTO students (name) VALUES ('Ali Hassan'), ('Sara Khan'), ('Aisha Malik'); INSERT INTO grades (student_id, subject, score) VALUES (1, 'Math', 95), (1, 'Science', 88), (2, 'Math', 99), (3, 'English', 78);

INNER JOIN — The Most Common JOIN

An INNER JOIN returns rows where there is a match in both tables. If a student has no grades, they won't appear in the result.

-- Get each student's name along with their subject and score SELECT students.name, grades.subject, grades.score FROM students INNER JOIN grades ON students.id = grades.student_id;

Result:

name subject score
Ali Hassan Math 95
Ali Hassan Science 88
Sara Khan Math 99
Aisha Malik English 78

Ali Hassan appears twice because he has grades in two subjects! The JOIN automatically multiplied the rows to match.

Using Aliases to Simplify Queries

Typing students.name every time gets long. You can create short aliases using AS:

-- s = students alias, g = grades alias SELECT s.name, g.subject, g.score FROM students AS s INNER JOIN grades AS g ON s.id = g.student_id;

This produces the exact same result — just easier to write!

LEFT JOIN — Include Unmatched Rows

A LEFT JOIN returns ALL rows from the left table (the one in FROM), even if there's no matching row in the right table. The unmatched values show up as NULL.

Imagine we add a student who has no grades yet:

INSERT INTO students (name) VALUES ('Usman Tariq'); -- Usman has no grades yet -- LEFT JOIN shows ALL students, even Usman with no grades SELECT s.name, g.subject, g.score FROM students AS s LEFT JOIN grades AS g ON s.id = g.student_id;

Result (notice Usman appears with NULLs):

name subject score
Ali Hassan Math 95
Ali Hassan Science 88
Sara Khan Math 99
Aisha Malik English 78
Usman Tariq NULL NULL

Other JOIN Types

JOIN Type What it Returns
INNER JOIN Only rows with a match in BOTH tables
LEFT JOIN All rows from the left table, NULLs for unmatched right rows
RIGHT JOIN All rows from the right table, NULLs for unmatched left rows
FULL JOIN All rows from both tables, NULLs where there's no match (not all databases support this)

For most school and beginner projects, INNER JOIN and LEFT JOIN are all you need!
