📬 What is an HTML Form? (From Chapter 11)

An HTML form is like a digital envelope. Everything the user types — name, email, password, choices — gets collected inside the <form> container and sent together to a server.

🏗️ The Form Container

  • All inputs must live inside <form></form>.
  • action="..." — URL where the data is sent.
  • method="get" — data visible in URL (for searches).
  • method="post" — data hidden (for passwords, private data).

🏷️ Labels Are Essential

  • Every input needs a <label> so users know what to type.
  • Connect them using matching for and id attributes.
  • Without labels, screen readers cannot describe the field — breaking accessibility.

🎛️ The Input Type Gallery (All from Ch 11)

The <input> tag is the most powerful form element. Its type attribute transforms it into many different controls:

Input Type What it creates Real-World Use
type="text" Single-line text box Name, city, username
type="email" Text box + email validation Sign-up, contact forms
type="password" Characters hidden as dots Login, account creation
type="number" Numbers only with spinner Age, quantity, grade
type="radio" Pick ONE from a group Gender, class section
type="checkbox" Pick MANY from a group Hobbies, preferences
<select> Drop-down menu Country, class, grade
<textarea> Multi-line text area Comments, messages, bio

🔑 Essential Form Attributes

🎯 Inputs — Must-Know Attributes

  • id="..." — Unique identifier, linked to its label's for.
  • name="..." — The key that identifies this field's data on the server.
  • placeholder="..." — Ghost text hint shown before user types.
  • required — Forces the user to fill in the field before submitting.

📋 Radio & Checkbox Rules

  • All radio buttons in a group share the same name.
  • Each radio/checkbox gets its own unique id and matching value.
  • Radio = mutually exclusive (pick one). Checkbox = multi-select (pick many).

🏆 Official Book Practice Exercises

🟢 Level 1: Recall (Easy)

What attribute on a <label> connects it to an <input>? What matching attribute must the input have? Why does this matter for accessibility?

Show Answer
The for attribute on the <label> must match the id attribute on the <input>. This connection means clicking the label text will focus the input — essential for screen readers and users with motor difficulties (they get a larger click target too).

🟡 Level 2: Application — Spot the Bug (Medium)

There are two errors in the code below. Can you identify and fix both?

<label for="city">Your City:</label>
<input type="text" id="location" name="city">

<p>Favourite sport?</p>
<label><input type="radio" name="cricket" value="cricket"> Cricket</label>
<label><input type="radio" name="football" value="football"> Football</label>
Show Answer
Bug 1: The label's for="city" does not match the input's id="location". Fix: change input to id="city".

Bug 2: Both radio buttons have different name attributes (name="cricket" and name="football"). Radio buttons in the same group MUST share the same name. Fix: give both name="sport".
